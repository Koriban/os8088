# tests/megahigh.txt - the OS88_HIGH / OS88_HIGHMEM exemption registry
# (docs/plans/KERN-MEGA-PLAN.md 14.51, 14.52)
#
# On kern_mega two bits of a package's class byte (+15) are the opt-in to
# extended memory (apps/os88api.inc): OS88_HIGH, the region may be loaded
# above 1MB, and OS88_HIGHMEM, its claims of 64KB or less may be too. The
# owner's rule: "opt in is fine but only with a full tier gate. They need to
# except themselves if they want to not opt in, and they need a damn good
# reason to do so."
#
# ONE LINE PER EXEMPTION: <kind> <package>  # <reason>
#
#   high     the package does not declare OS88_HIGH
#   highmem  it does not declare OS88_HIGHMEM
#
# A reason may run on over indented `#` lines below it. tests/unit/t_megahigh.py
# (full tier) is the gate, and the list turns ONE WAY: a line for a package
# that now declares is a FAILURE.
#
# THE BAR. A reason names a concrete thing in the code that breaks above 1MB -
# paragraph arithmetic on its own CS/DS or on a claim's segment, a far pointer
# kept for real mode, an IRQ vector stamped with its own CS, DMA or a BIOS
# call on a claim, a claim over 64KB stepped by segment arithmetic - with the
# place it is and what would retire the line. "Nobody looked" is not one: if
# you looked and found nothing, the answer is the declaration, after running
# the package on kern_mega (docs/BOCHS.md).
#
# NOT HERE, BY CONSTRUCTION: a parts LOADER (its source invokes OS88_REHOME -
# csload, wdload, scload, dosload, pxstein) is never asked for `high`, and is
# asked for `highmem` only when its own source claims. The gate's docstring
# says why; its program part is a package of its own and is checked as one.

# --- high --------------------------------------------------------------------

high apps/snddiag/snddiag.asm   # NEVER LOADED BY kern_mega: Sound Debug ships
    # only on the debug-sound disks, whose kernel is kern_big (SPEC.md 127.2),
    # and it reads a record only that disk's -DSNDDIAG SOUND.DRV keeps. A
    # kern_mega debug disk would settle it, run under Bochs (docs/BOCHS.md)

# --- highmem -----------------------------------------------------------------

# --- both --------------------------------------------------------------------

high apps/plan/plan.asm          # NOBODY HAS RUN PLAN ON kern_mega, and the
    # registry's own rule is that "nobody looked" is not a reason - so this
    # line says what WOULD settle it rather than claiming a defect. PLAN is
    # SHEET's 128KB fork (SPEC.md 81.75) and its whole existence is a machine
    # with 128KB of REAL memory; kern_mega is a 286+ with megabytes, where the
    # package that fork exists to fit is SHEET itself. So the declaration buys
    # the one configuration PLAN is not for, and costs a claim nobody has
    # exercised: pl_entry takes three claims and grows them with
    # OSAPI_MEM_REGROW, which is 14.51's own listed shape to check. Retired by
    # one MEGATRAP run with PLAN on the disk (`make megatrap`,
    # tools/os88bochs.py, docs/BOCHS.md) and the declaration.
highmem apps/plan/plan.asm       # the same, for the claims half: cells, text
    # arena and staging, each grown by OSAPI_MEM_REGROW rather than sized for
    # the worst document (SPEC.md 81.75.6). Retired with the line above.

high apps/ledger/ledger.asm      # PLAN's own mechanical fork (apps/RETIRED.txt's
    # `building` kind) - the two lines above apply here unchanged until LEDGER
    # is its own program.
highmem apps/ledger/ledger.asm   # the claims half, same ground: LEDGER is
    # PLAN's byte-for-byte fork and takes PLAN's three OSAPI_MEM_REGROW
    # claims unchanged, so the line above covers this one too. Retired with it.

high apps/fptest/fptest.asm      # AN INSTRUMENT, not a product
    # (apps/RETIRED.txt's `instrument` kind): the software-float gate, built by
    # its own target and carried by no disk. It measures os88fp.inc's eight
    # bytes against 126 fixed cases in its own bss and claims nothing, so there
    # is nothing above 1MB for it to be right or wrong about - and a bit
    # declared on a package no kern_mega disk carries could never be exercised.
    # Retired if FPTEST is ever shipped.
highmem apps/fptest/fptest.asm   # the claims half, same ground: FPTEST makes
    # NO heap claim at all - its 126 cases and their expected doubles are in
    # its own bss - so there is no claim for the bit to describe. Retired if
    # FPTEST is ever shipped and ever claims.

highmem apps/snddiag/snddiag.asm   # NEVER LOADED BY kern_mega: the debug-sound disks are kern_big, as for high

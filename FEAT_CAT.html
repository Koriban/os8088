The big gaps cross-cutting, not one package

The things worth knowing before diving into any one app below — each is a real design decision or an open plan, not a bug.

A real record database — planned, not built

planned SHEET's Data ▸ Form/Find/Extract and the eleven D* functions (SPEC.md §81.65) are a linear scan over a worksheet range — no index, no sorted access path. A true engine — a table with a key, a B-tree index, LOCATE/SEEK instead of a scan — is planned against dBASE III's real .DBF file format and command language, independent implementation (the Frotz precedent: not a port, a from-scratch reader/interpreter that is honest about which part is earned). docs/plans/DBASE3-PLAN.md is the design record; docs/plans/DATABASE-PLAN.md is the superseded first pass, kept for its still-valid kernel findings.

An integrated office suite — considered, dropped

dropped AppleWorks/Works/Symphony-style "one suite," costed as architecture C (separate packages + a shared Desktop + a suite-private typed clipboard, since SHEET alone is 61,866 of its 65,024-byte ceiling and one giant binary is arithmetically impossible). The owner dropped the idea in favour of the database engine above. docs/plans/WORKS-PLAN.md is kept as the record.

C64: no disk drive at all

gaps noted The C64 port loads .PRG files only — no .D64, no 1541/1571/1581. The serial bus is modelled correctly as empty (C64-SPEC §6.2), so LOAD"*",8 times out exactly like a real C64 with the drive switched off, rather than hanging. A host-side .D64 reader behind KERNAL traps is planned (docs/plans/C64-1541-PLAN.md) — read-only, no drive CPU, no second ROM sidecar. Fastloaders (code uploaded to the drive's own 6502) are the one class that plan's own §6 says it cannot reach without a second CPU context, which is costed there as a follow-on, not refused.

Apple II: no Disk II yet, but costed and unblocked

planned Read-only Disk II support (.DSK/.DO/.PO) is a pinned follow-up (APPLE2-SPEC §14) — the P5 boot ROM, the controller, the SAMESLOT timing trap and the 6-and-2 nibbliser are all specified down to the byte, so the wave is "a transcription, not a re-design." The size question that was supposed to gate it is answered: the package measures 44,324 of 61,440 resident this session (not the 53,284 the spec's own wave-5 table claims — the two disagree and the gap is recorded, not resolved, in APPLE2-SPEC §14.0), so Disk II's ~1,200 bytes fit with room to spare either way. tools/a2dsk.py (the fixture builder) and its gate are built; the nibbliser itself is not.

Printing — deliberately out of scope

by decision There is no print backend anywhere in this OS. SHEET's own gap list (SHEET-GAPS-PLAN §4) names six File-menu printing commands and calls them out of scope "by decision" rather than a gap to close. Nothing else with a Print item behaves differently.

Networking: real sockets, no TLS on this machine — by design

shipped, bounded ETHER.DRV is a real NE1000/2000 TCP/IP stack; Browser and Telnet speak real sockets through it, not a demo. An https:// URL is refused out loud rather than silently downgraded — there is no TLS stack here on purpose, because an RSA-2048 private-key operation is minutes on a 4.77 MHz 8088. TLS terminates on a host-side proxy instead (docs/plans/completed/PROXY-PLAN.md). Not a gap to close; a boundary the project drew on purpose.

The VBE 1024×768 driver — built, verified, not yet upstreamed

built, PR pending A full VBE 0104h desktop (1024×768, 16-colour planar, bank-switched) is built, measured on real VESA hardware (a Satellite 4025CDT and an 86Box Trident) and passes its own gates — VBEDRV branch, pushed to the fork. It has not been opened as a pull request upstream: the branch collides with a section-numbering change on jggonz/os8088's main and that renumbering sweep (245 citations on this side) hasn't been done. A separate, unrelated finding this session: VBE mode 0106h (1280×1024) can also be made to work by padding its scan line to a bank-clean stride — proven 19/19 on readback — which the VBE work's own SPEC section records but does not yet ship.
